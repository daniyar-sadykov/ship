# Завершить работу

Довести то, что сейчас лежит в рабочем дереве, до влитого `main`. По ходу
ничего не спрашивать, кроме случаев из раздела «Когда остановиться».

Если пользователь передал аргумент, считать его описанием работы для
сообщения коммита.

## 0. Разведка окружения

Выполнить молча, до любых изменений:

```bash
git rev-parse --is-inside-work-tree
git remote -v
gh repo view --json nameWithOwner
```

- Не git-репозиторий: остановиться и сказать об этом. Предложить `git init`.
- `gh repo view` вернул владельца и имя репозитория: путь **A**, через
  пулреквест. Эта команда разом проверяет всё нужное: `gh` установлен,
  залогинен, и `origin` ведёт на доступный репозиторий GitHub.
- Команда упала с любой ошибкой: путь **B**, локальное влитие. Причину
  запомнить, она понадобится в отчёте. Типичные причины: нет ремоута,
  `gh` не установлен, `gh` не залогинен, `origin` ведёт не на GitHub
  (GitLab, Bitbucket, локальный каталог), нет доступа к репозиторию.

Путь выбрать самому, не спрашивая. Назвать выбранный путь одной строкой
и идти дальше.

## 1. Осмотреться

```bash
git status --short
git branch --show-current
git log --oneline origin/main..HEAD   # путь B: git log --oneline main..HEAD
```

Понять, что уже закоммичено, а что нет, и на какой ветке работа.
Основная ветка может называться `main` или `master`, проверить:
`git symbolic-ref --short refs/remotes/origin/HEAD` или `git branch --list`.

## 2. Прогнать проверки

Смотреть, что реально есть в проекте, а не угадывать:

- `package.json`: прогнать те скрипты из `scripts`, которые есть, в порядке
  `typecheck`, `lint`, `test`, `build`.
- `pyproject.toml`, `pytest.ini`, каталог `tests/`: `python -m pytest -q`.
- `Makefile` с целью `test`: `make test`.

Проверок в проекте нет: сказать об этом одной строкой и идти дальше.
Проверка упала: дальше не идти. Починить, если причина очевидна, иначе
остановиться и показать вывод целиком.

## 3. Закоммитить остаток

1. Посмотреть, что уходит в коммит: `git status --short`, `git diff`.
   В коммит не должны попасть `.env`, ключи, токены, пароли, файлы с
   секретами. Нашлось такое: не коммитить, добавить в `.gitignore`,
   сказать пользователю.
2. Текущая ветка `main` или `master`: завести ветку под работу,
   `git switch -c feat/<короткий-slug>`. Для починки `fix/<slug>`.
3. Коммитить по одному коммиту на логическую задачу, не всё одной пачкой.
   Заголовок в формате conventional commits: `feat:`, `fix:`, `docs:`,
   `chore:`, `refactor:`, `test:`. Тело на том же языке, на котором
   написана остальная история репозитория (посмотреть `git log`).
4. Чистое дерево и коммиты уже есть: шаг пропустить.

## 4A. Путь A: пулреквест

```bash
git push -u origin <ветка>
gh pr create --fill
gh pr merge --squash --delete-branch
git switch main && git pull
```

Нюансы:

- У `gh pr merge` нет флага `-q`. С ним команда молча покажет справку
  вместо влития.
- `gh pr create --fill` берёт заголовок и тело из коммитов. Коммитов
  несколько, описание выходит невнятным: передать `--title` и `--body`
  руками.
- После влития проверить, что коммит действительно в `main`:
  `git log --oneline -3 main`.

## 4B. Путь B: локальное влитие

```bash
git switch main
git merge --squash <ветка>
git commit
git diff --stat main <ветка>   # должно быть пусто
git branch -D <ветка>
```

Нюанс: после `merge --squash` git не считает ветку влитой, потому что
её коммитов в истории `main` нет, остался только один сжатый коммит.
Поэтому `git branch -d` откажется её удалять, и нужен `-D`. Это
безопасно ровно при одном условии: `git diff --stat main <ветка>` вывел
пусто, то есть всё содержимое ветки уже в `main`. Вывод не пустой:
ветку не удалять, остановиться и сказать, что часть работы не влилась.

Ремоут есть и в него пускают: после влития `git push`. Ремоута нет
совсем: ничего не пушить.

В отчёте сказать прямо, что пулреквеста не было, и назвать причину из
шага 0. Если дело в `gh`, дать ученику две команды на будущее: установка
с https://cli.github.com и `gh auth login`.

## Когда остановиться и спросить

- Проверки падают, и причина не очевидна.
- В рабочем дереве есть незакоммиченная работа, которую делал не ты.
- Пулреквест или влитие не проходит из-за конфликта.
- `main` защищён, и влитие запрещено.
- Хук остановил коммит, и повод выглядит осмысленным, а не ложным.

## Чего не делать никогда

- `git push --force` в `main`.
- Переписывать историю: `rebase` чужих коммитов, `commit --amend` того,
  что уже отправлено.
- Удалять или править тесты, чтобы прогон стал зелёным.
- Коммитить секреты.
